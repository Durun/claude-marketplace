# durun-dashboard

手元で並行して動く Claude Code のセッションを一覧し、人間と Claude のやり取りを 1 か所にまとめるローカル Web アプリ。

## 起動

```sh
claude plugin marketplace add Durun/claude-marketplace
claude plugin install durun-dashboard@durun-toolbox   # フックと MCP を Claude Code に登録する
pnpm install
pnpm start                                            # http://localhost:7337
```

レート制限を表示するには、statusline のラッパーも登録する（任意）。

```sh
pnpm install-statusline
```

`pnpm start` の間は、コードを変えるとサーバーが自動で再起動し、開いている画面も読み込み直す。
書きかけの入力があるときは読み込み直さず、ヘッダーに読み込み直すボタンを出す。
画面を開いた直後と読み込み直した直後は、前に開いていたときのデータを先に出し、サーバーから届いたら差し替える。
PR、JIRA、Notion、GitHub の Inbox と、haiku が作るセッションの概要と返答の候補は、サーバーが `~/.durun-dashboard/cache.json` に覚えておき、サーバーを起動し直した後も、読み終えるのを待たずに出す。
古くなったものは裏で読み直し、変わったら画面を差し替える。「更新」を押したときは、読み直し終えるのを待つ。
会話ログは、サーバーを止めるときに読んだところまでの要約を `~/.durun-dashboard/log-summaries.json` に残し、次に起動したときは続きから読む。

`pnpm uninstall-statusline` でラッパーを外す。
設定を書き換える直前の内容は `~/.claude/settings.json.bak-durun-dashboard` に残る。

Windows でも同じ手順で動く。
フックと statusline のラッパーは Claude Code が Git Bash で動かすので、Claude Code と同じく Git for Windows が要る。
メモリの表示は macOS と Windows で出る。Windows では、メモリプレッシャーの代わりに物理メモリの使用率を出す。

## Tailscale 経由で開く

サーバーは `127.0.0.1` でだけ listen する。
ほかの端末から開くには、ダッシュボードを動かしている端末で、[tailscale serve](https://tailscale.com/kb/1312/serve) に tailnet の中へ中継させる。

```sh
tailscale serve --bg --http=7337 http://127.0.0.1:7337   # http://<端末の名前>:7337
tailscale serve --http=7337 off                          # やめるとき
```

tailnet の端末から、`http://<端末の名前>:7337`、`http://<端末の名前>.<tailnet の名前>.ts.net:7337`、Tailscale の IP のどれでも開ける。
サーバーは、この端末の tailnet での名前と IP を `tailscale status` から読み、その名前で届いたリクエストだけを受ける。
ダッシュボードには認証が無いので、tailnet につながる端末はどれも、セッションの起動や Claude へのメッセージの送信までできる。ほかの人と共有している tailnet では、ACL でこのポートに届く端末を絞る。
`http://` で開いた画面では、ブラウザが通知とクリップボードへのコピーを許さない。使うには、tailnet で HTTPS を有効にして `tailscale serve --bg 7337` で中継し、`https://<端末の名前>.<tailnet の名前>.ts.net` で開く。

## できること

| 画面 | 内容 |
|---|---|
| メニュー（ヘッダーの名前の左のボタン） | 検索、資料、ダッシュボードの編集（ホームとセッション）、スキンの切り替えをまとめる |
| 作業中と入力待ち（ヘッダーの件数） | 押すと、その状態のセッションを一覧で開く。セッションごとに最後の発言と要対応を並べ、質問への回答や、返答の候補を使った返信をその場で送れる。セッション名を押すと、セッションの画面へ移る |
| ホーム | ウィジェットを並べたダッシュボード。ヘッダーの名前を押すと開き、そのままもう一度押すと元の画面へ戻る。ウィジェットは、要対応の受信箱と、テーマごとのセッション一覧（状態、PR と CI、JIRA、コンテキスト使用率、タスクの進捗）と、JIRA の課題の一覧（JIRA Issues）。テーマは見出しを押すと折りたためる。セッションのカードの右上のピンを押すとピン留めし、テーマから外して一覧の先頭の「ピン留め」にまとめる。カードの左のチェックボックスで選んだセッションは、まとめてアーカイブできる。選んでいる間は、カードを押しても画面を移らず、選ぶかどうかを切り替える。カードはドラッグで並べ替え、ほかのテーマへ移せる。選んだカードをドラッグすると、選んだセッションをまとめて移す。新規セッションのボタンから、ディレクトリ、テーマ、最初の依頼、モデル、effort を決めて `claude --bg` で起動できる。モデルと effort の既定は Claude Code の設定に従う。JIRA Issues は編集の「追加」から置き、見出し、条件（JQL）、表示する件数をウィジェットの「設定」で変えられる。ウィジェットの「更新」を押すと、JIRA の情報を取り直して探し直す。メニューの「ダッシュボードを編集」を押すか、Cmd + Shift + E（Mac 以外では Ctrl + Shift + E）を押すと、ウィジェットを見出しのドラッグで動かし、右下の角で大きさを変え、× で外せる。ショートカットをもう一度押すと編集を終える。「追加」でウィジェットを選んでから置く場所を押すと、空いているところなら新しく置き、ほかのウィジェットの上ならタブとして重ねる。見出しをほかのウィジェットの上へドラッグして離しても、タブとして重ねる。重ねたウィジェットはタブで切り替えて見せ、タブをドラッグして、ほかのウィジェットに重ね直したり、空いているところへ離して単独に戻したりできる。ウィジェットの大きさは、ブラウザの幅と高さをそれぞれ 24 等分した升目で決まり、ブラウザの大きさに合わせて伸び縮みする。配置はブラウザに保存する |
| セッション | ホームと同じく、ウィジェットを並べたダッシュボード。ウィジェットは、セッション名と状態、テーマ、PR、JIRA、ターミナルで開くコマンドを並べた見出し、やり取りから haiku がまとめた概要（やっていること、いま）、TaskCreate のタスク、サブエージェント、資料、人間の依頼と Claude の発言を古い順に並べたチャット（ダッシュボードから届いた依頼も含む）、送信したメッセージ、コード、PR コメント、使用量。編集の仕方とウィジェットの大きさの決まり方はホームと同じで、配置はすべてのセッションで共通にし、ホームとは別にブラウザに保存する。初期配置は 1 画面に収め、チャット、コード、PR コメント、使用量と、送信したメッセージ、タスク、サブエージェント、資料を、それぞれ 1 つに重ねてタブで切り替える。コードや使用量へのリンクで開くと、そのウィジェットを重ねたところで、そのタブを選ぶ。資料には、present で出したものと、人間と Claude の発言に出たリンク（ダッシュボード自身のアドレスを除く）と、資料の「追加」で URL と題名を入れて足したリンクを新しい順に並べ、題名の先頭に favicon を添える。題名とサイトが同じリンクは 1 件にまとめ、押すと最後に出たリンクを開く。リンクの favicon は、ダッシュボードのサーバーがリンク先のサイトから取ってくる。発言の URL の後ろに空白を置かずに文を続けたときは、閉じていない ) と、日本語の句読点や括弧の手前までを URL とみなす。資料はドラッグで並べ替えられ、キーボードでは Alt + ↑↓ で動かす。行の右のピンを押すとピン留めし、ほかの資料より上にまとめる。並べ替えた後に出た資料は、ピン留めしていない資料の先頭に新しい順で足す。× で外した資料は、同じ URL のリンクが発言にまた出ても並べない。外したリンクは「追加」で足し直せる。Claude へのメッセージは、チャットの下に区切り線で分けて置いた送信欄から送る。スクロールするのはチャットの発言だけで、送信欄はいつも下に見える。送信欄で / を打つと、そのセッションで使える skills を補完する。チャットの Claude の発言は 1 つずつカードに入れる。各発言の左に時刻を出し、人間の依頼には既読も添える。送信したメッセージを押すと、チャットのその発言へ移る。発言の中のファイル名を押すと、コードの画面でそのファイルを開く。発言や資料の Notion のページへのリンクを押すと、`NOTION_TOKEN` を設定してあれば、ページの本文をウィンドウに浮かべて読める。長いページは途中までを出す。データベースへのリンクは、行を昔の Excel のシートに見立てた表にして 100 件まで出し、行の題名を押すとそのページを開く。リレーションとロールアップの列は出さない。インテグレーションに共有していないページは読めないので、ウィンドウのリンクから Notion で開く。修飾キーつきのクリックでは、今までどおりブラウザで開く。Claude が止まっていると、最後の発言から haiku が返答の候補を作り、クリックで入力欄に入れられる。セッション名は書き換えられ、空のまま Enter を押すと haiku が名前を提案する。人間も set_task も名前を付けていないセッションには、Claude の最初の応答が終わったとき（応答が長引くときは、始まって 5 分後）に haiku が名前を付ける。Claude Code が自動で付ける名前は、付いていないものとして扱う。アーカイブすると、バックグラウンドのセッションは `claude rm` で Claude Code の一覧からも消す。作業中のものは先に止め、作業ツリーに未コミットや未 push の変更が残るものは消さずに理由を知らせる。会話ログは残り、`claude --resume` で開ける |
| コード（セッションのウィジェット） | 選んだコミットの範囲の差分を表示し、行ごとに指摘を書いて Claude に送る。範囲は最近のコミットと、その 1 つ先に置いた未コミットの変更から選ぶ。既定は分岐点から未コミットの変更までで、Claude が request_review でコミットの範囲を指定したときは、その範囲になる。差分に無いファイルへのリンクで開いたときは、ファイル全体を表示する。Claude が show_branches でブランチを並べると、先頭のブランチの、比べる相手との分岐点から先の差分を表示する。「対象」で、並べたブランチと、このセッションの変更を切り替えられる。ブランチを表示している間は、差分に無いファイルもそのブランチから読み、送る指摘には、どのブランチの行かを添える。Claude が request_review でレビューを待っている間は、このセッションの変更を開く |
| PR コメント（セッションのウィジェット） | セッションが居たことのあるブランチの PR のうち、選んだ PR が開いていれば、未解決のレビューコメントのスレッドを並べる。PR が複数あるときは、上に並べた番号で切り替える。選んだ PR は、PR のウィジェットと共通にする。スレッドごとに、sonnet がリポジトリのコードを読んで、指摘の説明、事実確認、対応案を添える。「対応案で進める」を押すと、対応案のとおりに対応するよう Claude に頼む。指示を書いて送ると、その指示で対応させる。依頼を送ったスレッドには「依頼済み」を出す。スレッドは、Claude が応答を始めたときと終えたとき、レビューの状態が変わったとき、「更新」を押したときに読み直す。分析は、スレッドに返信が付くまで作り直さない |
| 資料（メニュー） | Claude が present で出した Markdown、mermaid、HTML を表示する |
| 使用量（セッションのウィジェット） | コンテキストの推移、トークンの内訳、5 時間と 7 日のレート制限 |
| 検索（Cmd + K、メニュー） | 検索窓から、セッション、要対応、資料、画面と、すべての会話ログ（`~/.claude/projects`）の題名、人間の依頼、Claude の発言を探し、選んだものの画面へ移る。Mac 以外では Ctrl + K で開く。会話ログで当たったものは検索の画面ですべて見られ、一覧にないセッションは、ターミナルで再開するコマンドをコピーできる |
| スキン（メニュー） | 画面の見た目を、デフォルトと Windows XP 風から選ぶ。Windows XP 風では、ヘッダーが画面の下のタスクバーになり、メニューはスタートボタンで開くスタートメニューになる。ウィジェットはウィンドウになり、重ねたウィジェットのタブはタイトルバーに並ぶ。名前のボタンは、ホームを開いている間は押し込まれ、ほかの画面では最小化したウィンドウのボタンのように膨らむ。選んだものはブラウザに保存する |
| 軽量モード（メニュー） | 回線が細い端末や非力な端末で開くときに、通信と描画を減らす。サーバーからの更新を 3 秒おきにまとめて受け取り、アニメーションを止め、イルカを出さず、メモリプレッシャーは 30 秒ごとに読み直す。タブが裏にある間は更新を受け取らないので、その間は通知も出ない。表に戻すと、つなぎ直して最新の状態にする。入れたかどうかはブラウザに保存する |
| メモリプレッシャー（ヘッダーの右端） | macOS のメモリプレッシャーを、通知領域に常駐するアイコンで示す。Windows XP 風では、タスクバーの時計の左に置く。目盛りの高さが割合を、色が段階（緑は正常、黄は警告、赤は危険）を表し、5 秒ごとに読み直す。押すと、物理メモリ、使用済みメモリ（App メモリ、確保されているメモリ、圧縮）、キャッシュされたファイル、スワップ使用領域の内訳を開く。内訳はアクティビティモニタと同じ求め方で出す。Windows では物理メモリの使用率を同じアイコンで示し、80% から警告、90% から危険の色にする。内訳は物理メモリ、使用中、利用可能で、タスクマネージャーと同じ値になる |
| イルカ（画面を泳ぐ） | Claude の色のイルカが 3D で画面を泳ぎ、ときどき大きくなる。ドラッグで動かせる。勢いよく払って離すと、その速さで進む向きへ体を向けて飛んでいき、水の抵抗で減速して、離す前に振り回していたら、その道のりの分だけ遠くまで飛び、画面の端では弱く跳ね返る。泳ぐ速さまで落ちたら、そのまま泳ぎ続ける。押すと吹き出しが開き、ダッシュボードの使い方や今の状態を haiku が答え、関係する画面へのボタンを出す。セッションの画面で聞くと、そのセッションの概要と直近の会話を踏まえて答える |
| 改善要望（右下のボタン） | ダッシュボードへの要望を書く。Windows XP 風では、ボタンをタスクバーの通知領域に置く。画面の要素をクリックして添えられる。送ると、そのときの URL、表示中のデータ、ウィンドウの大きさ、サーバーが動いている OS と一緒に `~/.durun-dashboard/feedback/` へ保存する |

要対応の受信箱には、Claude からの質問（ask_human と、Claude Code の AskUserQuestion）とレビュー依頼、権限の確認、入力待ちになったセッションの最後の発言、CI の失敗と変更要求、未読の資料が集まる。
worktree に入る（EnterWorktree）ときの権限の確認は、ほかのセッションがいない worktree ならダッシュボードが許可し、受信箱には出さない。別のセッションがいる worktree と、別のセッションが入ると決めてから 5 分以内の worktree には入らせず、どのセッションがいるかを Claude に返す。名前で入る先は、リポジトリの `.claude/worktrees/` と `.worktrees/` の下の同じ名前とみなす。git の外で名前を渡したときのように入る先を決められないときと、ダッシュボードが止まっているときは、今までどおり Claude Code が権限を確認する。
AskUserQuestion の質問には、バックグラウンドのセッションならその場で回答でき、セッションを止めてから再開して回答を渡す。端末のセッションでは、Claude Code の画面で答える。
受信箱と作業中と入力待ちの一覧では、長い発言を行の区切りで切って先頭だけを出し、「もっと読む」で全体を出す。
ブラウザの通知を許可すると、新しい要対応が届いたときに通知する。
セッションが作業を終えたときと、人間の回答、権限の確認、レビューを待ち始めたときは、どの画面を開いていてもトーストで知らせる。トーストを押すと、そのセッションへ移る。トーストは薄くなって消え、マウスを載せている間は消えない。
ウィジェットの右上のボタンで、ウィジェットをウィンドウに浮かべたり、最大化したりできる。枠に入っている間は、ウィンドウ化のボタンで浮かべ、最大化のボタンで画面いっぱいに広げる。ウィンドウの間は、ウィンドウ化のボタンで元の枠に戻し、最大化のボタンで広げる。最大化している間は、最大化のボタンは出ず、ウィンドウ化のボタンで最大化する前の状態に戻る。タイトルバーのダブルクリックでも、最大化と元の大きさを切り替えられる。資料や PR など、元の枠が無いウィンドウも最大化できる。
「追加」の「アプリ」から、ダブルクリックで起動するアイコンを好きな位置に置ける。アプリはメニューの「アプリ」からも起動できる。「新規セッション」はホームにもセッションにも置け、セッションで起動すると、そのセッションの作業ディレクトリとテーマを入れた状態で開く。「claude.ai/code で開く」は、セッションを claude.ai/code の新しいタブで開く。
アプリ「エクスプローラー」は、ダッシュボードを動かしている端末のファイルを一覧する。フォルダーはダブルクリックか Enter で開き、パスの欄に打って移ることもできる。左には、お気に入り、ホームディレクトリ、最上位の場所（Windows ではドライブ）を並べる。ファイルをダブルクリックすると、発言の中のファイル名を押したときと同じ開き方で開く。開いているセッションのリポジトリにあるファイルはコードの画面で開き、ほかはウィンドウに浮かべる。ファイルをセッションの「資料」へドラッグすると、資料に足せる。エクスプローラーは、メニューでは「アプリ」ではなく「エクスプローラー」の項目から開く。パスの欄の右の ☆ でフォルダーをお気に入りに登録すると、メニューの「エクスプローラー」に並び、そこから開ける。お気に入りはブラウザに保存する。セッションに置いたアイコンから開くと、そのセッションの作業ディレクトリを開く。
アプリ「文章校正」は、初めて読む人が文章を前から読み進められるかを、文ごとに 7 つの軸で調べる。文章の横の欄に、読み手が知っている語の用語集（1 行に「語：説明」か「語」）を書いておくと、読み手はその語を知っているものとして読む。用語集はファイルごとに持つ。「校正」を押すと、文章を文に切り、前から 1 文ずつ、それまでに読んだ部分と用語集だけを sonnet に読ませる。読み手は調べものをせず、一般常識だけで補う。答えが届いた文から、読み進めを妨げる文を赤、気にしてほしい文を淡い黄で塗り、指摘の付いた語句に印を付ける。軸のボタンで、その軸の指摘だけを見せられる。文を押すと、指摘と読み手のメモ（文の役割、前の文との関係、指す先、疑問）を右に出す。

| 軸 | 調べること | 失敗にするもの |
|---|---|---|
| 参照 | 既知のように書いた語句（指示語、説明の無い用語）の指す先が、そこまでの本文か用語集で分かるか | 別のまとまりに入るまで、または最後まで分からない語句。同じ項目の中で後から分かるものは注記にする |
| 回収 | 「何のことか」という疑問が、説明の区切り（段落、箇条書きの項目、節、文書の終わり）までに解けるか | 最後まで解けない疑問 |
| 近接 | 指す先が近くにあるか。係り方が 1 通りに読めるか | 指す先が離れていて、同じ語も所在の明示（「決定 7」など）も無い語句 |
| 骨組み | 文が、先に示された枠に入るか、枠を示すか | 無し（何のための文か分からない文を注記にする） |
| 連結 | 前の文との関係が分かるか。つなぐのに専門知識が要らないか | 無し（注記にする） |
| 語 | 曖昧な一般語、同じものの呼び分け、用語集と違う意味の語 | 同じものの呼び分け。曖昧な語は、言い換えの候補を添えて注記にする |
| 負荷 | 1 文の長さ、述語の数、初めて出る語の数、同じまとまりで解ける疑問を抱えたまま読んでいる数 | 無し（注記にする） |

読み途中で分からないことは失敗にしない。説明が続くと分かる疑問は区切りまで待ち、説明の区切りを過ぎても分からないものだけを失敗にする。疑問が区切りで解けたかは、TypeSafe の Jev に確かめさせる。`.env.local` に `TYPESAFE_AI_API_KEY` が無ければ haiku で確かめて続ける。指示語、和語の動詞、初めて出る語、述語の数は、形態素解析（lindera と UniDic）で拾って読み手に手がかりとして渡す。辞書は初めて校正するときに `~/.durun-dashboard/lindera/` へ取得する（約 190 MB）。形態素解析は崩れた文で誤ることがあるので、手がかりと数え上げにだけ使い、失敗を決める判定には使わない。曖昧な語と同じものの呼び分けは、読み終えてから文書全体を見て確かめ直す。
文章、用語集、校正の結果、人間のコメントと固定した文は 1 つのファイルにまとめ、`~/.durun-dashboard/proofread/` に自動で保存する。「ファイル」のメニューの「新規」で新しいファイルを始め、「最近使ったファイル」から前のファイルを開く。読んでいる途中で「中断」するかウィンドウを閉じても、読み終えた文の結果は残り、「続きから校正」でまだ読んでいない文だけを読む。結果の右下には用語集を表にして出し、文章の中の用語集の語に点線を引く。
指摘ごとに、修正版でどう直してほしいかを「コメント」で残せる。「コメントして無視」にした指摘は数に入れず、修正版でも直さない。「用語集へ」は、指摘の語句に説明を添えて用語集に足す。文の左のチェックボックスで文を固定すると、その文の指摘は数に入れず、修正版でも一字も変えない。校正を終えたら「修正版を作る」で、無視していない指摘とコメントに沿って opus（effort は medium）に文ごとに書き直させ、次の版を v2、v3 のタブに作る。固定した文は次の版に引き継ぐので、良い文を固定しながら校正と修正版を重ねられる。版ごとに文章と校正の結果が残る。「コピー」を押すか、「ファイル」のメニューの「v2 をエクスポート」から「クリップボードにコピー」を選ぶと、選んでいる版（ここでは v2）の文章をクリップボードにコピーする。
「表示」のメニューで「消費トークン」に印を付けると、ウィンドウの下端に、選んでいる版の校正で使ったトークン数を、モデル（sonnet、Jev、haiku）ごとに合計と内訳（入力、出力、キャッシュ読取、キャッシュ作成）で出す。校正している間は、問い合わせが返るたびに数が増える。「続きから校正」で読んだ分は前の分に足し、「修正版を作る」で使った分は数えない。印を付けたかどうかはブラウザに保存し、新しく開くウィンドウにも引き継ぐ。
文章校正のアイコンを送信欄の上までドラッグして離すと、メッセージに文章校正アプリを添付する。アイコンは元の位置に戻る。送信欄の + の「なんでも添付」でアイコンを押しても添付できる。添付したメッセージを受けた Claude は、MCP の `proofread` でアプリと同じ校正を走らせ、番号を振った指摘を受け取る。書き手の事情を知っている指摘には `comment_proofread` でコメントを返し（「コメントして無視」も選べる）、主要な指摘に返したら、文章は直さずにターンを終える。校正の結果と Claude のコメントはファイルに保存するので、「最近使ったファイル」から開いて、コメントに沿った修正版を作れる。アプリで校正を終えた版（v2 など）にも、Claude にコメントを頼める。Claude は `proofread` にファイルの id と版の番号を渡して、その版の指摘を校正し直さずに受け取り、`comment_proofread` でその版にコメントを返す。そのファイルをアプリで開いていれば、Claude のコメントをすぐに取り込み、人間がまだ保存していない変更も残す。
セッションの見出しのディレクトリ名を押すと絶対パスを、ブランチ名を押すとブランチ名をコピーする。発言と資料のコードブロックは、右上のボタンでコピーできる。
エージェントのウィジェットは、メインエージェント（セッションの状態と、進めているタスク）、サブエージェント、ツール（バックグラウンドの shell と Monitor）に分けて並べる。
資料に並ぶ Markdown ファイルの題名は、ファイル名に続けて最初の見出しを出す。
present にファイルで渡した HTML の資料は、同じディレクトリより下の音声、画像、動画を相対パスで埋め込める。ファイルをブラウザで直接開いたときと同じように、ダッシュボードでも鳴らしたり表示したりできる。PDF と PNG への書き出しでも、相対パスの画像を読む。「HTML でダウンロード」は、src と poster に書いた相対パスのファイルを HTML の中に入れ、どこに置いて開いても音が鳴る 1 つのファイルにする。32MB を超えるファイルは入れない。HTML が重くならないよう、音声は wav ではなく ogg で添える。
資料に並ぶ Notion のページへのリンクは、題名を付けずに足したものと、発言に URL だけを書いたものに、ページの題名を付ける。題名は `NOTION_TOKEN` を設定してあれば Notion から読み、読めないページでは URL に入っている題名を使う。
資料に足した JIRA の課題へのリンクには、課題のキーと題名をつないだ題名を付ける。題名は JIRA の API から読む。
PR と JIRA の課題のバッジには、番号やキーに続けて題名の先頭を 10 文字ほど出す。題名の全体はマウスを載せると出る。
JIRA の課題の画面では、本文とコメントの見出し、表、タスクリスト、コード、リンクを JIRA と同じ形で出す。表は昔の Internet Explorer で見た表に見立て、浮き出した外枠とへこんだセルを白地に並べる。太字と斜体は文字だけを出す。
課題の画面でステータスを押すと、今のステータスから移せるステータスを並べ、選ぶとそのステータスへ移す。
Claude へのメッセージを届けられなかったときは、どの画面を開いていても、理由（作業ディレクトリが信頼されていない、など）をトーストで知らせ、通知を許可していれば通知も出す。理由は、送信したメッセージの一覧にも残る。

## 改善要望の自動実装

改善要望のフォームで「自動で実装する」を ON にすると、ダッシュボードが `claude -p` のセッションを 1 つ起動し、たまっている要望をまとめて渡す。
セッションは要望の全体を見て作業計画を立て、似た作業をまとめて、1 つのウェーブとして実装する。

- まとまりごとに、セッションが変更をコミットする。コードレビューは依頼せず、人間の確認を待たずに次のまとまりへ進む。ウェーブで扱いきれない要望は、次のウェーブに回す。
- ウェーブを終えたら一区切りとし、残りの要望と新しく届いた要望を、新しいセッションで計画し直す。
- 済んだ要望は、セッションが最後の発言の「対応した要望:」に書いたものに限る。最後の発言を付けて `~/.durun-dashboard/feedback/done/` へ移る。
- 1 件も書かれていないときと、セッションが失敗したときは、同じ計画や失敗を繰り返さないよう、ON のまま待機する。新しい要望が届くか、フォームの「続ける」を押すと、次のウェーブを始める。
- 使用制限で止まったときは、ウェーブを区切らずに待ち、制限が明けたら同じセッションに「続けて」と頼んで続ける。待っている間は、新しいウェーブを始めない。
- 実装している間は、右下のボタンが「改善中」になる。Windows XP 風では、通知領域のボタンが、2 本の緑の矢印が輪になって回るアイコンになる。矢印は、1 秒に 4 コマで 45 度ずつ回る。
- OFF にすると、対応中のウェーブを終えたところで止まる。
- 歯車から、モデルと effort を選べる。既定は Claude Code の設定に従う。
- セッションは auto モードで動き、確認の要る操作は断られる。起動の記録は `~/.durun-dashboard/improve.log` に残る。
- ダッシュボード自身で起きた想定外のエラー（サーバーの 500、落ちる前の例外、画面の例外）も改善要望として起票する。同じエラーは 1 件にまとめて回数を数え、未対応のエラーの要望は 3 件までにする。対応の後に再発したものは、1 回だけ起票し直す。入力の誤りと claude の失敗は集めない。

## 登録されるもの

プラグイン durun-dashboard が登録するもの。

- フック: SessionStart、UserPromptSubmit、PreToolUse（AskUserQuestion と EnterWorktree だけ）、PostToolUse、Stop、Notification、SessionEnd。ダッシュボードが止まっていれば何もせずに終わる。
- MCP サーバー: `ask_human`、`present`、`request_review`、`show_branches`、`set_task`、`proofread`、`comment_proofread`。新しく起動したセッションから使える。

`pnpm install-statusline` が登録するもの（任意）。

- statusline のラッパー: 入力を `~/.durun-dashboard/statusline/` に保存してから、元の statusline コマンドに渡す。レート制限はここからしか取れない。登録しないと、使用制限のアイコンは空のまま登録の案内を出し、コンテキスト使用率は会話ログのトークン数から推定する。使用制限のアイコンの内訳には、5 時間と 7 日の枠ごとに、使用率の推移を、枠の始まりで 0%、リセットで 100% になる均等なペースの破線と並べたグラフで出す。

## 人間のメッセージが Claude に届く経路

| セッションの状態 | 届き方 |
|---|---|
| ask_human や request_review で待っている | ツールの結果としてすぐ届く |
| 入力待ちのバックグラウンドのセッション | `claude stop` で止めてから、`claude --bg --resume` で再開して渡す |
| 完了、中断、終了 | `claude --bg --resume` で再開して渡す |
| 作業中、権限の確認待ち、端末のセッションの入力待ち | セッションの受信ソケットに送る。作業中の Claude はツール実行の合間に読み、入力待ちの Claude は新しいターンを始めて読む |

再開して渡したメッセージは、人間が打った発言として、前置きを付けずに届く。
止めたバックグラウンドのセッションは、起動したときのオプション（`--model` や `--settings`）で起こし直される。
再開には数秒かかり、端末で `claude attach` していると、止めたときにその接続が終わる。

使用制限で止まったセッションには、制限が明けて 1 分たつと、ダッシュボードが「続けて」とだけ渡して続けさせる。
制限で止まったことは伝えず、前置きも付けない。
渡し方は上の表に従う。ただし、終わったセッション（端末を閉じたものなど）は起こさない。

送信欄には、今のモデルと effort が選択肢で出る。effort は statusline の入力から読むので、statusline のラッパーを登録していないと「不明」になる。
選び直して「切り替えて送信」を押すと、選んだモデルと effort で依頼を渡す。
バックグラウンドのセッションは起動したときのオプションを後から変えられないので、Claude Code は会話を引き継いだ複製を別の id で起動する。
ダッシュボードは、タイトル、テーマ、ピン留め、資料、未回答のやり取りを複製へ移し、元のセッションをアーカイブして、複製の画面へ移る。
切り替えられるのは、止めて再開できるセッション（完了、中断、終了と、入力待ちのバックグラウンドのセッション）だけ。

「分岐」を押すと、会話を引き継いだ別のセッションを、選んでいるモデルと effort でバックグラウンドに起動してメッセージを渡し、そのセッションの画面へ移る。
元のセッションは止めずに残すので、作業中のセッションと端末で開いているセッションからも分岐できる。
分岐したセッションには、元のセッションのテーマと、set_task で付けた JIRA の課題を付ける。名前は、ほかの新しいセッションと同じく、最初の応答の後に haiku が付ける。

受信ソケットは、Claude Code の [cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging) がセッションごとに開くもの。
この経路のメッセージは、Claude には別のセッションからのメッセージとして届く。
そのため Claude は、この経路の依頼では CLAUDE.md や設定を変えず、権限の確認も承認できない。
作業中のセッションは止めると作業が途切れ、端末のセッションはダッシュボードから止められないので、この経路で届ける。
bypassPermissions のセッションは、届いたメッセージを承認待ちで保留する。
Claude Code の設定で `crossSessionInbound` を `accept` にすると、保留せずに届く。

## 設定

`~/.durun-dashboard/.env.local` に書く。
ひな形は `.env.example` にあるので、写して使うものだけ値を入れる。

利用者ごとのデータ（状態、改善要望、statusline の記録、`.env.local`）は `~/.durun-dashboard/` に置き、ツールのリポジトリとは分ける。
置き場所は環境変数 `DURUN_DASHBOARD_DATA_DIR` で変えられる。変えたら中身を新しい場所へ移してから `pnpm install-statusline` をやり直す。

| 変数 | 内容 |
|---|---|
| `DURUN_DASHBOARD_PORT` | ポート（既定は 7337）。フックと MCP も同じ値を読むので、`.env.local` ではなく Claude Code を起動するシェルの環境変数に設定する |
| `JIRA_BASE_URL` | JIRA のサイト（例: `https://example.atlassian.net`） |
| `JIRA_PROJECT_KEYS` | ブランチ名や PR タイトルから課題キーを拾うプロジェクト（カンマ区切り） |
| `JIRA_EMAIL`、`JIRA_API_TOKEN` | 課題の題名と状態を表示するときと、JIRA Issues のウィジェットを使うときに設定する |
| `NOTION_TOKEN` | Notion のページをダッシュボードで読むときに設定する。Notion の[インテグレーション](https://www.notion.so/profile/integrations)のトークンで、読みたいページをそのインテグレーションに共有しておく |
| `CHROME_PATH` | 資料を PDF と PNG に書き出す Chrome。既定は macOS と Windows の標準の場所 |
| `TYPESAFE_AI_API_KEY` | 文章校正で、疑問が説明の区切りで解けたかを TypeSafe の Jev に確かめさせるときに設定する。無ければ haiku で確かめて続ける |

## 開発

```sh
pnpm check   # 型検査
pnpm test
```

OS ごとに違う情報の取り方と操作は、互換レイヤー `server/platform.ts` にまとめる。
ほかのコードは `process.platform` を見ずに、必ずここを経由する。claude の起動も `claudeCommand` を通す。
OS ごとの実装は `platformFor` で名前から選べ、外のコマンドは引数で差し替えられるので、`test/platform.test.ts` はどの OS の上でも全部の実装を確かめる。
互換レイヤーの外に OS の判定や claude の起動を書くと、同じテストが落ちる。
テストで claude を偽物にするときは、`test/fakeClaude.ts` の `useFakeClaude` で node のスクリプトを置く。
